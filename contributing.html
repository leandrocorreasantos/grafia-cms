Contribuindo

Guia para contribuidores do Grafia CMS.

Primeiramente, obrigado pelo interesse em contribuir com o Grafia CMS! 🎉

Este documento contém as diretrizes para contribuir com o projeto. Siga estas orientações para manter a qualidade e consistência do código.

Como Contribuir

1. Reportando Issues

Antes de abrir uma issue, verifique se já não existe uma issue similar. Ao criar, inclua:

  • Descrição clara do problema ou sugestão
  • Passos para reproduzir (se for bug)
  • Comportamento esperado vs. atual
  • Ambiente (SO, versão do Node.js, etc.)

2. Fazendo um Pull Request

  1. Faça um fork do repositório
  2. Crie uma branch a partir da develop: git checkout -b feature/nome-da-feature
  3. Implemente suas alterações seguindo os padrões de código
  4. Adicione ou atualize os testes conforme necessário
  5. Execute a suite de testes: npm test
  6. Faça o commit seguindo o padrão Conventional Commits
  7. Abra um Pull Request para a branch develop

3. Conventional Commits

Usamos o padrão Conventional Commits para mensagens de commit:

feat: adiciona autenticação por Application Password
^--^  ^------------------------------------^
|     |
|     +--> Descrição no imperativo
|
+--> Tipo: feat, fix, test, docs, refactor, chore, style

Tipos comuns:

  • feat — Nova funcionalidade
  • fix — Correção de bug
  • test — Testes
  • docs — Documentação
  • refactor — Refatoração
  • chore — Tarefas de build/config

Padrões de Código

DDD & Clean Architecture

O projeto segue estritamente os princípios de Domain-Driven Design e Clean Architecture:

src/
├── domain/ # Entidades, Value Objects, Interfaces
│ ├── user/
│ ├── post/
│ └── errors/
├── application/ # Use Cases (casos de uso)
│ ├── auth/
│ ├── user/
│ └── post/
├── infrastructure/ # Implementações concretas
│ ├── auth/ (JWT, bcrypt)
│ └── database/ (Prisma)
└── interfaces/ # HTTP, Middlewares, Rotas
├── http/
├── routes/
└── middlewares/

Regras Gerais

  • TypeScript estrito — Sem any a menos que absolutamente necessário
  • Imutabilidade — Prefira const, readonly e métodos que retornam novos objetos
  • Nomes em inglês — Código e comentários em inglês
  • Testes — Todo código novo deve ter testes unitários e/ou de integração
  • Sem dependências circulares — As camadas dependem para dentro (domain <- application <- infrastructure <- interfaces)

Estilo de Código

  • 2 espaços para indentação
  • Ponto e vírgula obrigatório
  • Aspas simples para strings
  • Nomes de classes em PascalCase
  • Nomes de funções/variáveis em camelCase
  • Interfaces prefixadas com I (ex: IUserRepository)

Como Rodar Localmente

Pré-requisitos

  • Node.js 18+
  • Docker e Docker Compose
  • npm 9+

Passos

# 1. Clone o repositório
git clone https://github.com/leandrocorreasantos/grafia-cms.git
cd grafia-cms

# 2. Instale as dependências
npm install

# 3. Suba o banco de dados
docker compose up -d

# 4. Configure as variáveis de ambiente
cp .env.example .env

# 5. Execute as migrações
cd apps/api
npx prisma migrate dev

# 6. Inicie o servidor de desenvolvimento
npm run dev

# 7. Execute os testes
npm test

Comandos Úteis

# Testes unitários
npm run test:unit

# Testes de integração
npm run test:integration

# Testes com cobertura
npm run test:coverage

# Compilação TypeScript
npx tsc --noEmit

# Lint
npm run lint
Dúvidas? Abra uma issue ou entre em contato!
